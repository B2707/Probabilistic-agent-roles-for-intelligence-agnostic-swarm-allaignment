# Interim messages-only replay protocol

The user authorized three random completed Sol runs and three random completed Luna runs, messages-only interim audits at a 10% random audit probability, the same Terra auditor, and flags without removals. They selected the original interim audits as the baseline rather than paying for a paired full-record rerun. Final audits are excluded.

Pinned source and published runs to `161435b685eaec663e6be4c6297af1e5d9257eda`. The manifest contains the single randomly generated selection seed `3210777441706422283`, the eligible runs and the selected runs. Selection is uniform without replacement within each worker model, excluding the publisher's disturbed original Luna seed-1 extras. Selected Sol A seed 3, B seed 3 and C seed 2; Luna B accepted Fast seed 1, C seed 2 and C accepted Fast seed 1.

The user's K=10% random-audit setting is `p=0.10` in the harness. The replay retains original report triggers and uses the original keyed random draw by run seed, round and agent slot with the new threshold. Original random audits at 1% are nested in this sample. All 619 original interim agent/round pairs are included among the 1,758 replay pairs. Of the replay pairs, 1,304 have a random trigger and 510 have a report trigger, with overlap deduplicated. A strict 10% of records is not imposed; this is the harness's Bernoulli probability.

Each audit uses a record truncated before the original audit phase of that round. Only target-authored `agent_message` and `message` text is emitted, with references, recipients, round and role-change markers. Messages sent through tools are retained, including DMs, board/progress posts and review comments. Tool calls/results, input prompts, code/PR action records and worker reasoning are excluded. Future conversion metadata is hidden. The original frozen auditor rules remain, with a scope clarification stating that absent actions/code cannot establish misconduct.

The replay uses `gpt-6.1-terra`, max effort, priority/Fast mode and the original maximum of 25 concurrent calls. It processes one run and one round at a time. Calls use the existing project backend in an isolated source extract and the available ChatGPT login. Every attempt records latency, usage and errors; completed verdicts are checkpointed for resume. No source run, world, verdict, agent removal, replacement or downstream conversation is modified. Existing removals and replacements remain as recorded; newly flagged agents are not removed.

Original audit logs omit usage, so exact baseline dollar cost is unavailable. New costs are API-equivalent estimates at the documented Fast rates, not a ChatGPT subscription invoice. Original interim time is estimated using the existing event-boundary timing script; new round-batch and request durations are measured. Different sample sizes and populations mean the comparison cannot isolate the effect of filtering. The report will mark the first novel removal-eligible flag and subsequent observations whose history could differ under intervention.

Preparation and canary checks passed for message retention, excluded evidence, role boundaries, future-conversion exclusion, quote references and immunity. The first live Terra audit completed in 20.78 seconds, returned a structured verdict and reported input/output/cache/reasoning usage. It is reused in the full replay. At launch the replay task is running; final results are pending.
